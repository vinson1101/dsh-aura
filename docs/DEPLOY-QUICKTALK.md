# Aura 单句 QuickTalk 部署说明

2026-11-25；版本 `0.35.4-visual.4`。以已测试 r11 源码和素材发布。用户已授权正式 DSH 安装及推送远端；视频跳跃保持现状，待正式窗口复测后决定是否重做。

## 范围

- 单句真实语音回答由 QuickTalk 渲染，并按分块音画播放；保留现有 ASR/TTS 和用户配置。
- 30 秒开口等待、待机/聆听/回答状态、五项标签互动和浅色主题菜单修复。
- 转侧身使用轻微校色 H3 素材；探镜头仍包含旧转身拼接，是已知视觉问题，未声称修好。
- 不把这些结果等同于连续通话验收。正式用户验收在部署后进行。

## 安装前

1. 检查部署记录、当前插件路径、DSH 任务和麦克风状态；备份 profile 与会话。不要退出整个 DSH 或影响其他插件任务。
2. 从确切提交或逐文件校验的冻结输入构建；保留旧 release、配置、私有凭据文件和回滚方式。凭据备份只放本机，不能进 Git。
3. 使用正式 desktop profile 的官方插件管理器热更新，避免直接修改软链造成旧模块缓存。保留 DSH 与插件版本兼容性。
4. 显式配置 `visualResponse.enabled=true`、`provider=quicktalk`、`remoteUrl=http://127.0.0.1:18765`；该地址是本机专用 SSH 隧道入口，不是公开服务。不要把隔离测试 workDir 或模型账号设置直接复制到正式 profile。
5. `AURA_QUICKTALK_TOKEN` 通过用户现有权限受限的私有存储读取，不写进提交、构建包、命令行或截图。沿用现有 ASR/TTS 凭据。

## 渲染依赖与恢复边界

QuickTalk 仍依赖 5090 和本机专用 SSH 通道。测试记录中的远端是独立任务进程；没有已确认的常驻托管/自动恢复保证。2026-11-25 发布准备检查发现本机18765未监听、局域网SSH超时；不能把历史健康结果当作当前在线。

恢复后先只读验证认证 `/health`、模型/底片哈希、服务脚本版本，再执行代表性单句。仅可恢复我们自己的连接或已获授权的 QuickTalk 进程；不得停止 vLLM 或其他服务。永久托管、开机启动及服务器升级不在这次插件发布内。

## 验证与回滚

- 自动化：`npm test`；`python3 test/quicktalk-server.test.py` 使用临时目录和本机假渲染器，不接生产模型。
- 已有 r11 浏览器测试使用真实播放器/素材和模拟任务状态，证明互动播放和抢占，不能代替真实收音与服务端生成。
- 正式安装后读取版本、provider、实际client和媒体哈希；检查浅主题菜单和互动结束回待机。
- 服务可达后验证真实单句音画和取消边界；不可达时必须标为“正式回答验证待恢复连接”，不能宣称可用。
- 回滚通过官方管理器重装保留的旧 release，并还原对应配置和私有凭据备份；只重载 Aura，不重启无关服务。

部署完成时在 `docs/deployments/` 保存无凭据记录，区分 source commit、artifact、pushed、deployed 和 user-accepted。本地 profile 备份位置可记录，备份本身不可推送。
