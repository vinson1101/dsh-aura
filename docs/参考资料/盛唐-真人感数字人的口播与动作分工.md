## 作者如何分工

| 环节 | 方法 | 用途 |
| --- | --- | --- |
| 配音 | Mac 上用 VoxCPM2 生成旁白，后续段落参考第一段声线 | 让预先写好的多段台词听起来像同一个人 |
| 出镜讲话 | Wan 2.1 I2V 14B 搭配 InfiniteTalk，根据已知音轨生成口播；以原定妆照约束分块生成 | 对齐可见的嘴形、下颌和语音 |
| 人物动作和转场 | H3 生成示意、回眸、走动等镜头；旁白继续时让画中人闭唇 | 用表演和剪辑维持在场感 |
| 空镜与合成 | 静物可本地做推拉，最后统一画幅、帧率、声音和字幕 | 节省离线出片成本 |

对口播，作者采用嘴和下巴无遮挡的自然闭唇定妆图、25 fps、81 帧滑窗、9 帧运动上下文及跨窗色彩匹配。对 H3 动作镜，文章列的是自托管 ComfyUI 工作流，包含 LoRA、采样步数和条件控制节点。它们不能直接当成我们正在使用的托管 H3 API 参数。

## 对 Aura 的判断

- 可以借用原始首帧约束身份、统一曝光和画幅，以及把无声动作与发声表演分开管理的方法。倾听、挥手、比心等素材可以加“无声”“嘴部无遮挡”“能否叠口型”等标签。
- 文章要求动作镜闭唇，是因为那时观众听到的是画外音。Aura 回答底片仍需保留讲话时自然的下颌、脸颊和肩颈运动。
- 三个案例都是已知台词的剪辑成片，有大量插镜。整片时长不能视作连续口播时长，文中没有给出任意新回复的首帧延迟、实时帧率或插话恢复数据。
- 对当前长底片实验，分别观察原短片循环点和音轨的自然停顿。前者检验动作连续性，后者检验口型驱动能否自然收口。延长底片可以推迟循环，是否改善发音同步须用同一句音轨对照。

另核对了 InfiniteTalk 官方仓库。项目支持图像或已有视频作为输入，目标涵盖长时说话视频生成；作者的云端组合与具体参数仍应按所用版本验证。[InfiniteTalk 官方仓库](https://github.com/MeiGen-AI/InfiniteTalk)

## Aura 试片约定（2026-11-21）

用户目前更认可万相接口生成的平静亲切口播。先用已认可的 Wan 3.0 女声回答做口播质量基准，H3 用于走动、示意、回眸、探镜头和比心等独立动作。Wan 2.1＋InfiniteTalk 是文章的口播复现路线，与 Wan 3.0 托管接口分开标注。以前本机的量化 InfiniteTalk 样片后半段存在明显色块和人脸失真。

此前 H3 平静口播提示词指定先吸气、聚焦、轻点一下头、眨眼、回到首帧。这会鼓励模型照顺序表演，单一变量对照尚未做。已认可的 Wan 女声样片则把重点放在原声发音、语速和指定停顿，头肩只随自然呼吸。[历史提示词参考（第 56–57 行）](InfiniteTalk-长视频口播实战.html)

**下一条平静回答的提示词模板**

> 沿用确认的短发正面定妆图与回答样片的机位、人物大小和原棚景。她正跟镜头另一端熟悉的人说话，语气平静亲切，目光自然。按所给原声的普通话发音、轻重和停连回答；嘴角、脸颊和下颌随发音协调，眉眼仅随语意有细微变化。肩颈自然放松。句中停顿时嘴唇自然相合，句末放松安静。保留原图的脸宽、下颌线、眼形眼距、唇形、栗色短发和轻盈刘海、黑方领、银项链及白里透红的肤色。固定构图、背景纹理、曝光、白平衡和光向。实际台词与音频另附。

**素材验收**。同一组定妆图、原声和参考棚景随任务保存。在开头、有声段、停顿、结尾和切换点分别比对：脸型五官、眼神与俏皮感、发型、肤色、头身尺度、肩颈连接、背景明暗与偏色。背景取固定空白区域抽样；核对主体另看人脸和肤色，避免全画面调色带偏皮肤。画面中多次出现固定节拍点头、脸部泛白、明显变宽或发型漂移时，保留为试验记录，暂不进入可选素材。跨片先看肩线、视线和手位能否接上。
