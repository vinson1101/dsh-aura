# Aura 数字人画面技术路线（2026-11-19 待确认）

目标是在 DSH 的 Aura 视频通话里保持同一个短发角色。她看向来电者，听时嘴唇稳定，说话时眼神、头肩和语气协调，用户插话后能停在自然姿态，再回答新问题。两段直播视频用于比较画面自然度；Muse 用于比较双向通话体验。

## 参考资料如何取舍

- [InfiniteTalk 长视频实战正文](InfiniteTalk-长视频口播实战.html)。以既有音频驱动人物画面，可以用同一句实际回复做整脸、头肩同步的离线对照。作者报告 37.7 秒视频耗时 584 秒；此数是该配置的离线吞吐，无法推出实时首帧延迟。[官方实现与示例](https://github.com/MeiGen-AI/InfiniteTalk)
- [Renoise 数字人 IP 正文](Renoise-数字人IP制作.html)。借用固定人物素材、短句试片和局部返工的方法。正文展示照片和脚本生成口播、再剪辑导出。帖首所提弹幕互动和持续直播缺少对应的端到端实现与延迟测量。
- [Meta 的 Muse 技术文章](Meta-Bringing-Your-Muse-to-Life.html)。借鉴角色参考与前段动作状态共同约束后续生成的思路，尤其关注说话和倾听之间的连续性。
- [LongCat 本机实测](Aura半身画面-LongCat实测.md)。保留为离线画面对照。本机此前的短片有开口过大、肩膀动作有限和推理慢的问题。MuseTalk、Duix 和 koubo 保留作局部口型或播报实现参考；进入通话前须用同一角色、同一音频比较。

## 拟按三个步骤验证

1. **倾听。** 使用现有[正面直视候选片](../../assets/previews/短发直播测试/无声倾听/短发正面直视-十秒无声倾听.mp4)。已确认的是上一版倾听动作，正面脸和眼神待确认。由通话状态触发倾听，验证长停顿和循环接点，防止无声动嘴。
2. **说话。** 先用这段正面视频和已有 Aura 中文回复，以 InfiniteTalk 的视频加音频路径制作 6–10 秒离线对照。保持竖幅、原声、句中停顿和半身景别。与之前的局部口型样片和直播参照原速比较，重点看首字、唇齿闪动、句中停顿、重音时头肩是否跟随，以及回到闭口时脸和短发是否稳定。保留原始停顿，不用剪辑修饰测试结果。
3. **通话。** 画质通过后再选能连续消费短音频块的驱动器。沿用现有 DSH 对话和 Aura 音频链路，以实际播放的音频为同步依据。每轮回复的声音和画面共用轮次标记，插话时取消旧轮并丢弃缓冲的声音和帧，从当前姿态过渡到倾听。实时生成若落后，先回到稳定倾听画面并继续语音。固定欢迎或互动可预制，临时回答须由当轮语音驱动。

## 验收与决策点

在桌面 Aura 里录 30–45 秒未经剪辑的通话，包含用户说话、等待、回答中途打断、追问和新回答。记录首段语音与画面何时出现、插话到旧声音停止、插话到旧口型停止、是否有旧帧回放。用原速半身画面判定自然度，再对齐脸部查看逐帧唇色与边缘变化。此前 34.4 秒测试由本地程序控制打断和播放，桌面麦克风端到端仍待验收。
