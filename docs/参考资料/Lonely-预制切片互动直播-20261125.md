## 来源事实摘要

作者使用 Renoise 中的 Wan 3.0 预制 19 段视频，按待机、快速回应、常见短答、点名回应分工，现场根据事件选片；没有准备的提问会跳过。OBS 和正式试播在文中仍是后续计划。这是固定回答的片段调度演示，不能据此认定已解决任意文本的实时口型。文章含工具推广；成本和部署主张未经本项目核实。

## 对 Aura 的设计建议（本项目判断）

- 保留混合路线：待机和无声互动复用高质量片段；任意任务回复继续走 Aura 真实语音与现有 QuickTalk 音画链路。不得用固定台词掩盖任务未回答。
- 扩展素材库之前，先修现有片段的进出姿态与选择规则。数量多不等于衔接自然，不照搬上万条素材的设想。
- 素材标签分两层：状态、人物版本、服装、背景、画幅、起止姿态属于准入条件；情绪、意图、动作属于通过准入后的选择条件。随机仅在合格候选中进行。
- 一个触发事件只选一个完整动作，不把多个不相关动作合并成一条“互动”。自然间隔从动作播放完成后计算，避免动作连续出现。
- 当前手动互动五项保留：转侧身、探镜头、比爱心、招手、微笑；每项可独立验收，不因菜单已有入口就视为素材合格。
- 对未知任务不得跳过。回答准备期间可播放克制待机；新音画就绪后由回答状态抢占，不能继续播无关动作。

这些是调度设计建议，不表示本轮改动了状态机。现有代码与部署以对应 release 记录为准。
